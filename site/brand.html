02 / Product system

The vocabulary does work.

Explain the plain meaning on first contact. The Japanese names identify different activities; they should help people navigate, not make them decode the interface.

Term Purpose How to present it
Kata A focused practice unit with a time limit and an evaluation. Show the title, type, challenge and time. Keep the primary action clear.
Scroll An external learning app embedded in Dojo. Lead with what it teaches. Published content and access depend on the operator’s catalogue.
Skill level Junior, mid or senior preference used in kata selection. A challenge preference. Never label it as a verified qualification.
Belt A rank computed from sustained and varied practice. White → yellow → green → brown → black. Always pair rank color with its name.
Verdict The sensei’s assessment of one attempt. Passed, Passed with notes or Needs work. No numeric score; no implication of belt promotion.
Milestone A one-time recognition of a particular moment. Name the event. It is separate from rank and from challenge difficulty.
Engawa The anonymous code playground. Explain it as “a place to try a snippet” before asking someone to learn the name.

Kumite remains planned. It does not belong in a shipped-feature list. Scroll infrastructure and the available learning catalogue are different claims; say which one you mean. See these terms in the product presentation.

05 / UI & usability

Keep the work
in the foreground.

The interface should distinguish learning, practice and progress without adding a layer of spectacle. These examples show the brand treatment; they are not live kata controls.

Illustrative kata card

Find the race condition.

Identify the assumption that fails when two requests reach the same resource together.

CODE · MID · TIMED PRACTICE

Understand the kata loop
  • One clear next action. Lead with the work the person came to do. Leave navigation and secondary actions quiet.
  • Separate intent from rank. Level helps select a challenge. Belt reflects practice. Verdict describes one attempt.
  • Use space before boxes. Small 4–6 px corners and surface stacking. No glow, celebratory gradients or ornamental dashboards.
  • Keep states explicit. Empty catalogues, unavailable scrolls and failed execution need plain descriptions and a recovery action.
  • Protect readability. Visible keyboard focus, generous touch targets, labels with color, no horizontal page overflow at 320 px.
  • Reserve motion for a job. A short functional transition is enough. Honor reduced motion; keep frequent practice surfaces quiet.

06 / Voice

Direct about the work.
Respectful of the person.

Dojo is candid, technical and comfortable with imperfection. Humor may lighten the delivery, but it must not replace a precise observation or soften an evaluation.

The examples above are authored voice specimens. Product copy should name the problem, the outcome and the next step. Public marketing explains katas and scrolls before relying on their names. Never invent testimonials, user counts, guaranteed skill improvement or a learning catalogue.

08 / Integration

Use the source.
Regenerate the exports.

The public site and brand guide are ready for the existing GitHub Pages workflow. The application integration follows the same mark and semantic tokens, without moving domain logic.

1. Generate and verify assets

Run from the repository root after changing canonical geometry, palette or the social composition. The generator uses the existing API SVG renderer; install workspace dependencies first. Outputs are checked in so GitHub Pages can serve the static directory. 

pnpm install --frozen-lockfile
node scripts/brand-assets.mjs
node scripts/brand-assets.mjs --check
pnpm test:scripts

The check fails on stale exports, missing downloads, broken local anchors and root-relative URLs that would escape the project base path. It never treats a missing file as a clean result.

2. Integrate into the React application

The existing LogoMark reads canonical geometry, and LogoWordmark keeps its component API. Reuse those components in headers, navigation and login. Use semantic classes such as text-accent and text-primary; keep long content in the sans family. 

import { LogoWordmark } from './components/Logo'

<LogoWordmark markSize={24} />
<LogoWordmark showMark={false} />

Dojo already supports Washi and Sumi through data-theme and its theme controls. This delivery does not switch every existing screen to a new default or alter evaluation and progression. Check the affected screen in both themes before changing token values.

3. Integrate session sharing

The dynamic renderer lives at apps/api/src/infrastructure/http/routes/share.ts. It must keep the actual kata, verdict, quote and visibility rules. The project PNG is for project marketing and must not replace a personal session’s image. Applying the new visual treatment to that renderer is a separate integration step.

4. Publish with GitHub Pages

The existing workflow uploads site/ when its files change on master. No framework build or new hosting service is needed. Preview the directory under a /dojo/ path before publishing; all local links and assets remain relative. 

python3 -m http.server 3118 --bind 127.0.0.1 --directory site
# Open http://127.0.0.1:3118/

# Intended project URLs after publication:
# https://rodacato.github.io/dojo/
# https://rodacato.github.io/dojo/brand.html

Update canonical URLs and absolute social-image URLs if the Pages host changes. Publishing requires the normal repository review and merge. A local preview is not proof of deployment.

5. Apply repository and app icons

The generated favicon (SVG and ICO) and the 180 × 180 apple-touch icon PNG are wired to the project site and web app. The icon SVG exports are source material for an app installation icon; they do not establish a PWA or promise offline use. For GitHub, upload brand/social-sumi.png as the repository social preview and inspect its crop. That repository setting is not changed by committing these files.

Keep the identity aligned as one change: update canonical files, regenerate exports, verify the site, then review the affected product surfaces. The guide demonstrates the system; it does not create a second component library.
